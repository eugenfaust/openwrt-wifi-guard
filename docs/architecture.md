# Architecture

## Process and event data path

One stdlib-only static Go daemon owns the registry. It discovers sorted `hostapd.*` objects and spawns `ubus subscribe <argv...>`. A 256 KiB-bounded JSON-line scanner feeds a 128-item channel. Only successful authorization changes online identity; pre-authorization/probe events never mutate the registry. The child is canceled/reaped on failure/replacement and accepted buffered events are drained before replacement or final shutdown saving.

`get_clients` snapshots accept only boolean `authorized: true`. Positive observations across APs precede negatives to handle roaming. Failed AP snapshots leave their clients' last known online state intact; complete successful discovery retires removed APs, including the case where all APs disappear. Periodic renewal repairs subscriptions whose object names stayed the same but IDs changed. There is no transactional CLI subscribe-ready acknowledgement: periodic reconciliation remains the gap-recovery mechanism.

Startup import has a finite event window. Queued events during the first snapshot attempt are imported silently. Each initial AP awaiting its first successful snapshot remains in persisted `bootstrap_pending`; only that snapshot is suppressed, not subsequent live authorizations. This avoids both startup storms and indefinite suppression when one AP fails. The policy necessarily cannot distinguish truly new from preexisting clients inside the silent startup window.

## Owner-loop application layer

The monitor's owner loop also consumes bounded control commands. Device reads return value copies, history is reverse chronological, and mutation validation is strict. Rename/trust are saved before a success reply. Pre-publication save failures roll back the mutation; a typed `storage.PublishedError` after rename keeps the published value in memory and dirty for a durability retry, while reporting that success was not confirmed. There is no network blocking action or arbitrary command API.

Telegram delivery is an injected nonblocking alert callback. A bounded worker queue performs network requests separately. A second bounded, serialized configuration worker performs UCI subprocesses and configuration fsync outside the registry owner loop; queued changes take their baseline when executed, preventing stale concurrent writes. A short mutex protects live settings/notifier pointers, never disk or network I/O. Unchanged effective settings do not write flash, recreate the notifier or discard its queue. Genuine credential/configuration changes cancel the previous generation, including its in-flight tests; accepted pending messages from that generation are intentionally not transferred to another recipient/token. Tests and automatic notifications share one notifier serialization gate per generation, including explicit tests while automatic delivery is disabled. Shutdown cancels work instead of waiting through retries; the in-memory outbox remains best-effort.

## UCI and secret handling

### Optional DHCP hostname hints

A separate cancellable worker reads `uci -q -c <config-dir> export dhcp` and the regular `/tmp/dhcp.leases` file without changing DHCP/DNS or making network lookups. Each source is limited to 1 MiB, subprocess runtime to two seconds. Static host names take precedence over active leases; invalid names/MACs and expired leases are ignored. The default refresh interval is 15 seconds. Failed refreshes keep the bounded cache for at most two minutes, never beyond a lease's own expiry.

Only the registry owner copies hints onto already known Wi-Fi entries. Metadata refreshes cannot create wired devices, authorize clients, change trust/deny policy or send discovery notifications. Changes use ordinary dirty-state batching. `hostname` is a separate optional JSON field; `friendly_name` remains exclusively operator-controlled. LuCI and Telegram prefer the manual name over hostname; an empty manual name restores hostname fallback. Hostnames are untrusted hints, not proof of identity. Alerts do not wait for DHCP; a late lease may appear in the UI on the next refresh without resending the original alert.

`internal/config` reads only named application options using fixed argv and bounded output. Writes use stdin batch commands inside a private staging directory and private UCI delta path; staged values are read back, restricted to 0600, synced and atomically published. Only this application's file is changed. Empty credential options can disappear under libuci and are treated as empty; the enabled flag remains mandatory. External concurrent UCI writers require coordination.

No endpoint/transport override is exposed in UCI or RPC: production Telegram uses official HTTPS, with redirects disabled and error redaction at the HTTP boundary. The public settings response contains enabled/chat_id/token_set only. The UI never reloads or reads back the token. A typed post-publication configuration error immediately pauses old delivery. Readback alignment uses a fresh, bounded service-lifetime context rather than an expired RPC context. If current disk state cannot be recovered, delivery pauses and public settings fail closed until a successful reconfiguration/readback or application restart; an uncertain save is never reported as confirmed.

## Concrete LuCI bridge

Native LuCI → authenticated uHTTPd/ubus → native rpcd ACL → `/usr/libexec/rpcd/wifi-guard` → `wifi-guard rpc call METHOD` → root-private Unix socket → owner command channel.

The executable plugin advertises argument types with exemplar JSON values because rpcd infers type from values, not type-name strings. uHTTPd injects `ubus_rpc_session` after ACL checking; the CLI strips only that transport field before strict application validation. It is not treated as authorization by the private daemon and never appears in a response. Read-only ACL has no mutate/test or generic file/UCI/exec permissions. No new TCP port is opened.

New socket directories are 0700 and sockets 0600. Existing paths must be owned by the process and not writable by other Unix users. Eight active socket requests and a 16-item owner command queue bound concurrency. Idle clients are closed on shutdown; peer disconnect or extra request bytes cancel the server request context so still-queued mutations are skipped. Once a mutation starts, cancellation is best effort and does not guarantee rollback. Requests and responses are size/deadline bounded. Root/same-UID processes and broad native administrator ACLs remain trusted, not sandboxed.

The four LuCI routes (Overview, Devices, History, Settings) reuse the installed theme/fonts/components; no additional web framework, remote fonts or build-time npm tree is needed. Each route loads only its own required RPC reads; Overview reads devices and history independently. Devices filters the current list client-side; History pages the latest 500 events locally because RPC has a bounded limit but no offset. Russian source translations live in `luci/po/ru/wifi-guard.po`, with a compiled LuCI catalog shipped in the package at `/usr/lib/lua/luci/i18n/wifi-guard.ru.lmo`. Regenerate the tracked catalog with the OpenWrt 24.10 LuCI `po2lmo luci/po/ru/wifi-guard.po luci/i18n/wifi-guard.ru.lmo` utility when changing strings. Unavailable settings keep editing/save/test disabled until a successful recovery. Overlapping refreshes cannot overwrite already loaded unsaved settings inputs. HTML boolean attributes use null for false, since `disabled="false"` is still disabled in real DOM; this has both regression and real-browser coverage.

## Storage and packaging

Versioned JSON, bounded history and persistent known identities share one atomic file. Temp + fsync + rename + directory fsync prevents partial-file publication; critical changes flush at 30s by default, last-seen-only changes checkpoint at 15m. Power loss before a batch remains a loss window. Matching 16 MiB read/write limits preserve the previous file on capacity failure; identities are not silently evicted. Before loading mutable state, the daemon takes a nonblocking kernel flock on a private adjacent `.lock` file; a second owner fails before subscription/configuration activity, even with a different or disabled RPC socket. Atomic read-only dumps do not take the writer lock. The lock inode is never unlinked while in use; process death releases the kernel lock automatically. Do not manually delete a lock file while its owner is alive.

Official OpenWrt 24.10.2 SDK creates actual opkg IPKs. The explicit host Go toolchain builds static ARM64 without CGO/VCS stamping; the SDK handles package metadata and payload construction. Daemon and LuCI are separate packages. procd supplies memory-related environment limits, respawn and shutdown grace; reload restarts only WiFi Guard. The opkg conffile is retained, and dynamically created state is never shipped as an empty replacement.

## Deferred scope and verification boundaries

No Telegram callback mutations, permanent blocking, vendor identification, selected-device/reappearance alerts, or SSID/IP/band enrichment. Native router installation/UI/ACL/upgrade were tested without changing network settings. Real Telegram test and isolated automatic-notification receipts were confirmed using server-side credentials; disruptive Wi-Fi/hostapd/reboot tests and long-term resource behavior remain separate acceptance gates. See verification.md for facts rather than inferring end-to-end success from tests or cross-compilation.
