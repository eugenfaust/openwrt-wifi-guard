# OpenWrt WiFi Guard

Монитор новых авторизованных Wi-Fi-клиентов для OpenWrt: уведомления Telegram, реестр устройств и нативная страница LuCI. Go без сторонних модулей и CGO; новых публичных портов нет. Ethernet-клиенты не отслеживаются, автоматической блокировки нет.

## Что реализовано

- Обнаружение всех AP и подписка через `ubus subscribe`, а не `ubus listen`.
- Авторизации `sta-authorized`, периодическая сверка `get_clients`; probe/auth/assoc сами по себе не добавляют устройства.
- Тихий начальный импорт, нормализация MAC, отсутствие повторных обнаружений при переподключении и роуминге.
- Постоянный реестр, ограниченная история, атомарное сохранение и редкие записи `last_seen` на flash.
- Получение hostname из DHCP только для уже известных Wi-Fi-клиентов, без изменения DHCP/DNS. Приоритет имени в интерфейсе и Telegram: заданное вручную → hostname → «Устройство без имени». Hostname участвует в поиске, но не даёт доверия: отдельный статус — «Доверие не задано».
- Асинхронная очередь Telegram, ограниченные повторы/таймауты, UCI и тестовое сообщение.
- LuCI: отдельные разделы «Обзор», «Устройства», «История» и «Настройки» со стандартной темой и русским переводом. Обзор показывает текущие подключения; в устройствах есть поиск по имени/MAC/интерфейсу и фильтры по подключению, доверию и блокировке. История показывает последние 500 событий с локальным разбиением по 25 записей. Имя, доверие и подтверждённая разблокировка доступны в устройствах, Telegram и тест — в настройках. Токен не возвращается в API чтения.
- Нативная аутентификация/ACL rpcd и закрытый Unix-сокет; нет общего exec/file/UCI-доступа для ограниченных ролей.
- Отдельные `.ipk` демона и LuCI, собранные официальным SDK, служба procd.

**На AX3000T/OpenWrt 24.10.2 проверены** установка, работа демона, реальные авторизации телефона, отсутствие ложных новых устройств от probe, действия LuCI, отказ неавторизованного доступа и сохранение данных при переустановке. Получение реального тестового сообщения и автоматического уведомления из изолированной копии реестра подтверждено пользователем; автоматические регрессионные тесты используют поддельный Bot API. Перезагрузка роутера, Wi-Fi и hostapd намеренно не выполнялась на живом домашнем интернете.

## Сборка

Нужны Go 1.23+, Make, Python 3 и Node.js 20+ только на компьютере разработчика. На роутере Python/Node/Go не нужны.

```sh
make check smoke arm64
# Linux x86-64 и зависимости официального SDK:
make packages
```

Готовые файлы:
- `build/wifi-guard-linux-arm64` — статический бинарник.
- `build/packages/wifi-guard_0.3.0-r3_aarch64_cortex-a53.ipk`
- `build/packages/luci-app-wifi-guard_0.3.0-r3_all.ipk`

Поддерживаемый первый target — `mediatek/filogic`, `aarch64_cortex-a53`, OpenWrt 24.10.2. Пакеты APK и другие архитектуры пока не заявлены. Архив SDK проверяется по закреплённому SHA-256; `.ipk` создаёт сам SDK, а не самодельный архиватор. Подробности и команды — [docs/installation.md](docs/installation.md).

## Установка и Telegram

Используйте настоящий адрес роутера и заранее проверьте свободную flash/RAM и зависимости. Не подставляйте предполагаемый адрес сети.

```sh
export ROUTER='root@YOUR_ROUTER_ADDRESS'
scp -O build/packages/wifi-guard_0.3.0-r3_aarch64_cortex-a53.ipk build/packages/luci-app-wifi-guard_0.3.0-r3_all.ipk "$ROUTER":/tmp/
ssh "$ROUTER" 'opkg install /tmp/wifi-guard_0.3.0-r3_aarch64_cortex-a53.ipk /tmp/luci-app-wifi-guard_0.3.0-r3_all.ipk'
# Только управляющий rpcd, не сеть/Wi-Fi/DNS/firewall:
ssh "$ROUTER" '/etc/init.d/rpcd reload'
```

Стандартный postinstall OpenWrt включает и запускает только службу WiFi Guard. По умолчанию Telegram выключен, начальный импорт не рассылает сообщения. После обновления LuCI может потребоваться новый вход.

В **Services → WiFi Guard → Настройки**:
1. Сначала нажмите Start в диалоге со своим ботом.
2. Внесите числовой Chat ID и токен непосредственно в авторизованную страницу настроек.
3. Включите Telegram, сохраните и нажмите **Send test message**.
4. Проверьте получение явно помеченного тестового сообщения в нужном чате.

Токен в чат агенту не отправляйте. Поле Bot token после чтения остаётся пустым: пустое сохраняет прежний токен, отдельная галочка очищает его. Origin-bound browser vault не является API экспорта секретов для серверных процессов. Для управления через недоверенную сеть используйте HTTPS или SSH-туннель: HTTP сам по себе не шифрует токен. Версия 0.3.0-r3 установлена на согласованный роутер: все четыре раздела открылись в существующей теме, сохранность настроек и соответствие установленных файлов пакетам проверены. Русский каталог покрыт локальными тестами; браузерная проверка выполнялась с прежним английским языком LuCI.

Состояние хранится в `/etc/wifi-guard/state.json`, секретный UCI — `/etc/config/wifi-guard`, сокет — `/var/run/wifi-guard/control.sock`. Файлы/сокет 0600, новый каталог реестра 0700. По умолчанию приложение не меняет сеть, firewall, DHCP и DNS. При отдельно включённой и подтверждённой блокировке меняются только управляемые MAC ACL в wireless и адресные runtime-правила; Wi-Fi не перезапускается.

## Ручной тест без установки

Бинарник и состояние можно разместить в отдельном защищённом каталоге `/tmp`, указав `-state` и `-socket` внутри него. Для изолированных уведомлений задайте отдельный закрытый `-uci-dir`; иначе применится конфиг установленной службы. Ctrl-C сохраняет состояние и завершает только тестовый монитор. Не запускайте два процесса с одним файлом состояния; `/tmp` теряется после перезагрузки.

Основные параметры:
- `-state`, `-dump` — реестр; dump не включает конфигурацию и токен.
- `-uci-dir`, `-uci`, `-ubus` — каталоги/исполняемые файлы без shell-интерполяции.
- `-socket` — закрытый Unix-сокет; пустое значение отключает RPC.
- `-bootstrap import` — тихое первое окно; `notify` считает начальных клиентов новыми, но не забывает известные MAC.
- `-reconcile 60s`, `-retry 5s`, `-resubscribe 5m` — сверка и восстановление подписки.
- `-flush 30s`, `-checkpoint 15m` — изменения подключений и более редкое сохранение только `last_seen`.
- `-history-limit 500`, `-command-timeout 5s` — границы истории и каждой команды.
- `-test-telegram` — тест по уже внесённым UCI-секретам, без токена в аргументах.

## Ограничения

MAC не является аутентификацией: смена приватного адреса может выглядеть как новое устройство. Известное не равно доверенному; доверие не разрешает доступ к сети. Добавлены включаемые отдельно подписанные кнопки Telegram «Доверять / Заблокировать», подтверждение и сохраняемый запрет по MAC до ручной разблокировки. Включение, защищённые административные MAC, ограничения ACL и отдельные аппаратные проверки описаны в [инструкции](docs/telegram-actions.md). Определение вендора, уведомления о повторном появлении и обогащение SSID/диапазоном/IP пока не реализованы. Hostname — необязательные и недостоверенные данные DHCP, а не проверенная идентификация устройства. Очистка ручного имени возвращает отображение hostname, если он доступен. Уведомление использует имя, доступное на момент его подготовки; позднее появление hostname не вызывает повторной рассылки.

Начальный импорт имеет конечное окно: сбой одной AP не подавляет последующие живые события бесконечно. Список ожидающих первого снимка AP сохраняется между запусками. Ошибка снимка не переводит её клиентов offline; успешный пустой список AP переводит.

Очередь Telegram ограничена и не является долговечным outbox: выключение/переполнение может потерять ожидающее сообщение. При неоднозначном сетевом таймауте повтор может продублировать уже принятое сообщение. Дедупликация подключений не гарантирует exactly-once для внешнего HTTP. Ошибки и ответы API обезличиваются, секретные URL не логируются.

Атомарная запись не сохраняет ещё не записанный пакет при внезапном отключении питания. История ограничена, реестр известных MAC не очищается автоматически. Лимит чтения/записи 16 МиБ; превышение не заменяет старый рабочий файл. Ошибка fsync после rename считается неопределённостью долговечности, а не поводом откатить память к более старому файлу. Следите за местом и резервными копиями.

## Диагностика, обновление и удаление

Проверьте `/etc/init.d/wifi-guard status`, `logread -e wifi-guard`, `ubus -v list wifi-guard` и права файлов. Отсутствующий объект LuCI требует проверки/перезагрузки только rpcd, не сети. Неисправный реестр не сбрасывается молча. Логи и реестр содержат идентификаторы устройств — не публикуйте их.

UCI является conffile opkg; динамический реестр не поставляется пустым файлом и сохраняется при обновлении. При изменённом конфиге opkg может оставить новый стандартный вариант рядом с суффиксом `-opkg`, не заменяя ваш рабочий.

```sh
/etc/init.d/wifi-guard stop
opkg remove luci-app-wifi-guard wifi-guard
```

Изменённый конфиг и реестр могут остаться специально: удаляйте их только намеренно после резервного копирования. Ни установка, ни удаление не должны сбрасывать wireless/firewall/DHCP/DNS. Исходный локальный `AGENTS.md` сохранён, но исключён из Git из-за наблюдавшихся данных устройств.
